Scope: the working tree as it stands (14 modified and 4 untracked files, uncommitted), `PRODUCT_SPEC.md` as the yardstick, and the 22 open Notion tasks for this project.

Method:

## Executive summary

1. **Core features work.** Generate, refine, validate, analyze, export, deck chat and the API-key gate all function, and nothing returned a 500 in normal flows. Backend tests: **326 passed / 22 skipped**. `next build` is clean.
2. **The Commander path is the weakest part, and the scorecard hides it.** The Commander corpus is synthetic: skeletons padded with 54–87 copies of one basic, each listed twice. The commander picker scores the archetype's colors instead of the commander's color identity, so a U/R request comes back as a mono-blue deck with 36 Islands. The scorecard still says Mana 100.
3. **The validator gets several basic rules wrong.** It rejects legal 61+ card decks and snow basics. It accepts 16+ card sideboards and a commander inside its own 99. Commander eligibility is wrong in both directions (non-commander planeswalkers accepted, "can be your commander" cards rejected).
4. **Security, P1:** a deck share link returns the raw API key as `owner`, and that key is also shipped in the browser bundle. Save/history return a 500 on the real dev DB because its schema predates the current save feature.
5. **Spec alignment is about 47%:** 6 of 34 checklist items are Done, 20 Partial, 8 Missing. The engine has outgrown the spec (simulator, optimizer, evaluation), but user-facing spec items are still missing:
   - alternatives
   - include/exclude controls
   - save/share UI
   - version history
   - Commander brackets
   - the sideboard guarantee for 60-card formats
   - an evaluation harness at real scale

## Bugs

Severity:
- **P0:** data loss or security exposure in a deployed build.
- **P1:** wrong results users will hit, or a security issue.

No deploy exists yet (MEMORY.md), so nothing is rated P0.

### Security

**S-1 · P1 · A share link returns the raw API key as `owner`.** The P1 Notion task is confirmed, and the exposure is wider than it describes. R(agent)
- Repro: `POST /v1/decks/save` with header `X-API-Key: test-key-123`, then `GET /v1/decks/shared/{token}` with no key → 200 `{"owner":"test-key-123",…}`. `GET /v1/decks/saved/{id}` with no key also returns `owner` and `share_token`.
- Root cause:
  - `main.py:301-317` stores `owner=key`.
  - `deck_history_service.py:60-74` `_to_dict` serializes `owner`.
  - The read routes at `main.py:328-341` are unauthenticated.
  - `tests/test_deck_diff_history.py:103` asserts `owner == "alice-key"`, so the bug is locked in by a test.
- It's broader than the task:
  - The web app sends `NEXT_PUBLIC_API_KEY` (`web/src/lib/api.ts:18`), so the key is in the JS bundle anyway.
  - Every browser user shares one key, so `history` returns everyone's decks.
  - With auth off, `delete(owner=None)` deletes any deck by id.
  - A failed save logs the key in SQLAlchemy's INSERT parameters.
- Fix:
  1. Store `sha256(key)[:16]`, and backfill existing rows.
  2. Use a public serializer without `owner`/`share_token`.
  3. Gate or remove `/v1/decks/saved/{id}`.
  4. Move gated calls behind a Next.js route handler so the key never reaches the browser.
  5. Fix the test.
- Effort: S for the first two steps, M for the proxy.
- Production exposure: none. There is no deploy, so the Notion task's "verify live" step is moot today.

**S-2 · P1 · Save, history and shared return 500 on the real dev DB.** R(agent)
- Root cause: `var/mtg_deck_builder.db` still has the deck-lab `saved_decks` schema (`session_id`, `title`, `deck_json`, `chat_history`). `create_all` never alters an existing table, so inserts fail: `OperationalError: table saved_decks has no column named share_token`.
- Tests miss it because the `isolated_history` fixture uses an in-memory DB.
- Fix: Alembic, or at minimum a startup schema check that migrates or recreates the legacy table.
- Effort: M.

**S-3 · P1 · `/api/data-status` (unauthenticated) returns the full `database_url`.** R(agent), and visible in my live run.
- On Postgres this would include the password.
- Location: `card_repository.py:775`, `models.py:180`, `web/src/lib/types.ts:222`.
- Fix: `make_url(...).render_as_string(hide_password=True)`, or drop the field.
- Effort: S.

**S-4 · P2 · Endpoints that spend LLM tokens are ungated and have no size limits.** R(agent)
- `generate`, `refine` and `analyze` call Anthropic, but only chat, evaluate, optimize, prose and save are gated.
- `analyze` defaults to `deep_analysis=True` and has no rate limit.
- There is no `max_length` on `prompt`, `refinement_prompt`, `message`, `deck_text` or `notes`, and no list caps. A 1 MB prompt to generate → 200 in 4.3s.
- `GET /v1/cards?limit=100000` → 32,731 cards in 4.7s. Optimizer `rounds`/`sim_runs_per_eval` are unbounded.
- Fix: `Field(max_length=…)`, `Query(le=…)`, rate-limit analyze, and decide on gating for the LLM paths.
- Effort: S.

**S-5 · P2 · No LLM timeouts.**
- `anthropic.Anthropic(api_key=key)` at `llm_service.py:68`, `critic/clients.py:220,290` and `deck_rationale.py:188` uses the SDK default of 600s with 2 retries.
- These are sync routes on a 40-thread pool, so a provider stall can pin workers for minutes.
- Fix: `timeout=20, max_retries=1`; the fallbacks already exist.
- Effort: S.

**S-6 · P2 · The rate limiter is per process and keyed on `req.client.host`** (`rate_limiter.py`, `main.py:179`).
- Behind any proxy, all users share one bucket.
- Effort: M (before deploy).

**S-7 · P3 · Affiliate unwrapping is loose.** suspected
- `_canonical_destination` matches hosts by substring (`"pxf.io" in netloc`).
- It double-decodes (`parse_qs` followed by `unquote`).
- The inner destination isn't restricted to tcgplayer.com.
- None of this is tested (overlaps REFACTOR-PLAN RP-006).
- Effort: S.

### Deck engine

**B-1 · P1 · The Commander corpus is synthetic padding.** R
- Repro: `sqlite3 var/mtg_deck_builder.db` on the land packages of `archetypes` shows 11 of 12 Commander archetypes have one basic land at an average of 54–87 copies ("Commander Spellslinger: Mountain 70"). The UI shows this directly: "Mountain 100% • 70 avg".
- Root cause: `app/data/tournament_decks.curated.json` Commander records are 12–45 real cards padded to 99 with one basic, and each record appears twice. So "Evidence decks: 2" is one synthetic list, and commander "popularity" is at most 2.
- Fix: replace with real Commander lists (an offline EDHREC/Moxfield export, per spec §9), or at least strip the padding and dedupe. Until then, label Commander provenance as "template", not "corpus-backed".
- Effort: M (data), S (labelling).

**B-2 · P1 · Commander picker drops a requested color. A U/R request returns a mono-U deck with 36 Islands.** R
- Repro (UI): Commander, colors U+R, default brief.
  - Result: Talrand, Sky Summoner (mono-U), 36 Island plus Command Tower, zero red cards.
  - The corpus shell's red core (Niv-Mizzet, Young Pyromancer, Lightning Bolt) was filtered out.
  - The scorecard still reads **Mana 100, Quality 93**.
- Repro (API): `{"format":"commander","colors":["W","B"],"playstyle_tags":["tokens"]}` → Yawgmoth (mono-B), 36 Swamps, no white.
- Root cause: `deck_generator.py:1044-1045` computes `color_fit` and `exact_color_fit` from `candidate.colors` (the archetype's colors, `["R","U"]`) instead of the commander card's color identity.
- Fix: score against `get_card(candidate.commander).color_identity`, require it to be a superset of the requested colors when any commander fits, and make the mana score penalize unused requested colors.
- Effort: S.

**B-3 · P1 · The LLM-written strategy text contradicts the actual deck.** R
- Same run as B-2. The summary says "Mizzix of the Izmagnus leads the deck… finish with Grapeshot and Niv-Mizzet triggers", but none of those cards are in the 99.
- The API reviewer saw the same thing: a Haldir deck described as "Built around Sheoldred, Whispering One".
- Root cause: `compose_from_scratch` / `refine_compose` produce the label and strategy text before commander selection and color filtering, and nothing checks the prose against the final list.
- Fix: regenerate or trim the summary after the final list is fixed. As a cheap guard, drop any sentence naming a card that isn't in the deck.
- Effort: S–M.

**B-4 · P1 · The validator rejects legal constructed decks of more than 60 cards.** R
- Repro: a 64-card Modern burn list returns `errors: ["Constructed decks must have exactly 60 cards in the mainboard."]`.
- Root cause: `deck_validator.py:112-113` uses `!=` where the rule is a minimum. `DeckResponse` (`models.py:418`) repeats this, so export, refine and chat 422 on a 61-card list.
- The open Notion test task "reject mainboard with 61 cards" asks to lock in the wrong rule. **That task should be rewritten as "accept 61+".**
- Effort: S.

**B-5 · P1 · Sideboard size isn't enforced.** R
- Repro: a 16-card (and a 20-card) Modern sideboard returns `is_legal: true`.
- Root cause: `deck_validator.py:114-115` only warns, and only when the count isn't 0 or 15.
- Fix: more than 15 is an error; fewer than 15 is allowed.
- Effort: S.

**B-6 · P1 · Copy-limit exemptions are wrong.** R
- Repro: 28 Snow-Covered Mountain → "exceeds the 4-copy limit". 36 Relentless Rats → same error.
- Root cause: `deck_validator.py:59` and `deck_generator.py:1567` match the literal text "Basic Land", but snow basics read "Basic Snow Land". The "A deck can have any number of cards named…" exemption isn't handled.
- `optimizer/constraints.py:139` has its own correct snow rule, so there are three diverging rule sets.
- Fix: one shared `copy_limit(card, format)` used by all three places (with Seven Dwarves = 7).
- Effort: S.

**B-7 · P1 · Commander rules: commander in its own 99 is accepted, and eligibility is wrong both ways.**
- Repro (R): Kenrith as commander plus Kenrith in the mainboard → `is_legal: true`.
- R(agent): `/v1/commanders?search=Ajani` lists non-commander planeswalkers (279 accepted). The 17 cards that say "can be your commander" are rejected.
- Root cause: `deck_validator.py:86-110` never adds the commander to `name_counter`. `card_repository.py:522-527` accepts any legendary planeswalker.
- Also missing: partner/background pairs (175 such commanders exist in the pool, but the request takes one name) and companion rules.
- Effort: S, plus M for partners.

**B-8 · P1 · Colorless corpus shells win single-color requests.** R(agent)
- Repro: `{"format":"modern","colors":["U"],"playstyle_tags":["control"]}` → "Control Eldrazi" (Wastes, Urza lands; blue only in Force of Negation).
- Root cause: `card_repository.py:204-207`. `set() ⊆ requested` is always true, and line 215 adds a +10 bonus on top.
- Fix: require overlap with the requested colors unless "C" was requested.
- Effort: S.

**B-9 · P1 · With no LLM key, the brief's colors, budget and archetype are ignored.** R(agent)
- Repro: "a cheap mono-green stompy deck under $40" → colorless Eldrazi, $578.
- Root cause: `llm_service.py:224-228` returns an empty intent when there is no client.
- This matters because §25 makes the deterministic fallback a requirement, and CI and any keyless deploy hit this path.
- Fix: a regex fallback for guild/shard names, "mono-X", "$N" / "under N", and format names.
- Effort: M.

**B-10 · P1 · Constraints get lost along the way.** R(agent)
- **Refine forgets the budget and excludes:** a $50 burn deck refined with "add 4x Lightning Helix" came back at $194.50 with no warning. `DeckResponse` doesn't carry the original constraints (`deck_generator.py:790-843`).
- **The sideboard ignores excludes and budget:** excluded Smash to Smithereens still appeared in the sideboard. `deck_generator.py:967-1008` passes an empty `set()` as the excluded set.
- **Commander ignores `include_cards` entirely:** Atraxa plus Doubling Season → not in the deck, no warning (`_build_commander_mainboard`, `:1157-1228`).
- Fix: persist request constraints on the deck, and thread `excluded`, budget and includes through every builder.
- Effort: M.

**B-11 · P1 · Constructed sideboards are often empty or off-plan.** R
- Repro (live sweep): Standard W/U control → 0 sideboard cards. Pioneer B/G midrange → 0. Legacy → 6 (agent).
- A burn sideboard included 4 Aether Vial and 4 Walking Ballista (agent).
- The spec requires sideboards for 60-card formats (§1, §27), and the validator doesn't warn when the sideboard is empty.
- Root cause: `deck_generator.py:994-1010` draws only from the role pools of corpus archetypes.
- Fix: rank by color and role from the full legal pool, always fill to 15, and warn when that's impossible.
- Effort: M.

**B-12 · P2 · Budget leaks.** R(agent)
- 7,325 of 33,794 cards (22%) have no price, including Sol Ring, Arcane Signet and Cyclonic Rift. They pass the budget check and count as $0 (`deck_generator.py:1606,1618`). Kenrith with a $150 budget was estimated at $251, with 19 unpriced cards.
- `include_cards` skip the budget check (Notion task "include_cards bypasses budget": **still present**). Builtin anchors are merged into `include_cards`, so the warning names cards the user never asked for and caps them at 2 copies ("Forced card(s) exceed requested budget: Monastery Swiftspear").
- Fix:
  - Treat a missing price as unknown and report "N cards unpriced".
  - Keep anchors separate from user includes.
- Effort: S.

**B-13 · P1 · The optimizer default path produces junk and claims it's legal.** R(agent)
- Repro: with `MTG_USE_OPTIMIZER_DEFAULT=true`, R aggro with a $60 budget returned Abandoned Sarcophagus, Abrade, Abstergo Entertainment, Access Tunnel… (alphabetical fill) at $104.98.
- Root cause: `optimizer_default_path.py:44-96` hard-codes `is_legal=True` and `legality=100`, never calls the validator it's given, passes no recipes, and returns no sideboard.
- This flag is off by default, but MEMORY lists it as the "make it default" lever.
- Fix: seed it with builtin or corpus recipes, run the real validator, and fall back to the legacy generator when the result is illegal or over budget.
- Effort: M.
